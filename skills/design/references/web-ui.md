# Web UIの実装基準

優先順位はユーザーの明示指示、既存のデザインシステム、DADS。既存アプリの動作とAPI契約を維持する。[共通原則](principles.md)を制作前と検証時に使う。

- 別指定のない日本語Web UIは `IBM Plex Sans JP`、`"Noto Sans JP"`、OSの日本語ゴシック、`sans-serif` の順でfallbackする。本パッケージの採用判断でありDADS公式の指定ではない。本文・UIは原則16 CSS px以上、本文の相対行高は1.5以上。読み物は [HTML資料](html-documents.md) の1.7を出発点にする。
- 使用するウェイトだけを用意し、フォントのライセンス・配信方針を確認する。CDNを必須にせず、自己ホスト時もライセンス表示を保つ。`font-display: swap` を使い、取得失敗でも本文・UI・日本語入力が使えるようにする。
- 装飾書体、斜体、背景テクスチャ、不要なアニメーションを既定にしない。必要な動きは `prefers-reduced-motion` に対応する。
- 背景、本文、境界、リンク、primary、success、warning、errorなど役割で色を定義する。色だけで状態を示さない。本文リンクは下線を保ち、訪問済み・hover・focusも識別可能にする。
- `:focus-visible` とYellow-300＋Blackの二重フォーカスを採用する。DADSの公式コンポーネント例を確認し、背景ごとに視認性を測定する。
- 見出し、ランドマーク、ラベル、説明、エラーをセマンティックHTMLで結び付ける。見た目の補正で部品の規定を壊さない。
- 氏名・住所・読み・和暦・文字種は目的と例外から決める。姓・名の分割、フリガナ、全角・半角指定を慣例だけで要求しない。既存API制約は明示する。

新規Web UIはライトとダークの両方を実装・検証する。既存UIの局所修正は対象テーマを維持し、未依頼のテーマ追加へ広げない。ダークはアプリ側の派生テーマであり、公式DADSの完成済みテーマとは表現しない。

テキストと背景は4.5:1以上、必要な非テキスト要素と隣接色は3:1以上を実測する。主要なタップ領域は44 × 44 CSS px以上を採用目安とする。物理単位へ換算しない。[検証](verification.md)で幅、拡大、キーボード、IME、フォント失敗、全状態を確認する。

既存スタックを優先し、公式サンプルや依存は必要時だけ導入する。参照先の現行版と利用条件を確認する。独自CSSでも、採用した規則・トークンと案件の差分を既存READMEやデザイン文書へ記録する。
