# 検証と証拠

共通原則と選んだ媒体の基準を使い、課題／期待／方法／結果と証拠／未確認を既存QAや納品説明へ残す。技術検査、制作者確認、実利用者検証を別の証拠とする。実利用者が参加していなければその限界を示し、参加者や理解度を作らない。利用者調査の未実施だけで承認済みの制作を止めない。

設計構想やモックのレビュー結果は、動作中の機能や公開版の検証結果とは分けて記録する。As-Isの観察、To-Beの採用判断、実装、実画面確認をそれぞれの証拠で示し、構想を実現済みと報告しない。

## Web・HTML

- 320 CSS px幅、200%拡大で欠落・重なり・意図しない横溢れを確認する。
- キーボードだけで主要課題を完了し、フォーカス順・表示・修正・復帰を確認する。
- Webフォントの通常読込と意図的な取得失敗で、fallback、文字化け、レイアウト、FOITを確認する。
- 日本語IMEの入力・変換・確定・再編集とcomposition中の値保持を確認する。
- 通常、hover、focus、入力済み、disabled、readonly、エラー、成功の状態を確認する。色だけでエラーを示さない。
- 対象テーマそれぞれでテキスト4.5:1以上、必要な非テキスト3:1以上をツールで測定し、主要なタップ領域44 × 44 CSS px以上を確認する。
- 必要な説明・条件・根拠へ目次や直リンクから戻れるかを確認する。複数ビューはID、分類、件数、説明、状態、リンクを比較し、元データの変更が全ビューへ反映されるか確かめる。
- 保存を実装した場合は再読み込み、受入条件に含む別端末や競合、失敗時の入力保持を確認する。静的表示を保存機能として報告しない。

## 資料・図解・教材

口頭補足なしで主要な関係を説明し、前提・根拠を見つけ、判断や次の行動を選べるか確かめる。元資料の数値と関係、長いラベル、読み順、出力時の欠けを確認する。モデルは計算の正しさと仮定を別に検証する。進捗率は分母と件数比／工数比を示す。

スクリーンショットから操作性や適合を断定しない。未実施・失敗・検証不能を明記する。公開までが対象ならCI成功、commitと公開版の一致、公開画面の主要操作を確認し、URL・日時・commit・CIリンクを示す。
