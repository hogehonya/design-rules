# HTML資料の表示設計

[共通原則](principles.md)、[Web UI](web-ui.md)、骨子を作る場合は [読む資料の構成](document-story.md) を読む。

HTMLプレゼンも縦に連続して読む1ページの資料とする。「要点 → 全体像 → 具体例 → 設計判断」を一続きにし、目次と補足の折りたたみで読む深さを選べるようにする。主要な結論を隠さず、決定・提案・未決を区別する。ページ切替、固定16:9、枚数制限、スライドエンジンを追加しない。

説明だけなら1ビューでよい。作業・進捗、LP、一覧は用途がある場合だけ加え、ビュー数を固定しない。作業・進捗は状態、担当、期限、完了条件、依存、関連設計を必要に応じて示す。未提供の値を推測で埋めない。

分類・親子関係・IDは情報構造、カード／リストは表示形式、要約／詳細は情報量として別々に決める。切替で分類・本文・状態・リンクを失わない。複数ビューは同じ元データを使い、既存Markdown・JSON・CMSなどの第二の正本を作らない。

- 本文は16 CSS px以上、行高は1.7を出発点にする。補足と操作も読める大きさを保つ。
- 日本語と長いURLを自然に折り返す。余白と列数は内容と幅に合わせ、狭い画面は1列から始める。
- 横並びカードはGridなどで高さを揃え、本文が余白を吸収してリンクを下端へ置く。固定高、切り捨て、位置合わせの空行を使わない。縦リストへ同じ高さ揃えを強制しない。
- 操作は明示したリンクやボタンに置き、カード全体をクリック対象にしない。
- 新規HTMLのライト／ダーク、端末設定への追従・手動選択、モバイルを確認する。テーマ設定の保存と資料・TODOの保存は分ける。

静的資料に機能しない保存操作を見せない。更新時点と正本を示し、設計済み・未実装・未検証・動作確認済みを区別する。保存依頼時だけ既存の保存先・認証・権限・履歴・競合を確認し、成功前に保存済みと表示しない。失敗時は入力を残す。表示生成だけでDBやAPIを追加しない。
